# Архитектура АРМ обработки досье

## 1. Назначение и границы

АРМ обработки досье — отдельное настольное приложение. Оно не связано с Oracle Data Modeler/DMRS-проектом Global11_demo и не является частью Java EE-системы «Территория».

Основные функциональные контуры, выявленные по предоставленным материалам:

- пользовательский интерфейс WPF/WinForms;
- поиск персон и досье;
- модель предметных данных (Case, Dossier, адреса, документы, комментарии, сценарии);
- взаимодействие с UMMS через SOAP;
- адресный поиск через Elasticsearch/FIAS;
- импорт/экспорт и синхронизация с мобильным модулем;
- работа со съёмными носителями;
- печать/формирование паспортных и MRZ-данных;
- журналирование и конфигурация.

## 2. Основные компоненты

### UI и запуск

В материалах упоминаются App, MainWindow, LoginWindow и ConfigWindow. MainWindow отвечает за поиск, пагинацию, кэширование, вкладки досье, импорт/экспорт и синхронизацию. ConfigWindow хранит настройки адресов сервисов, максимума результатов и параметров отображения.

Риски: синхронные сетевые вызовы в UI-потоке, обработка исключений диспетчера, жёстко заданные пути и тестовые значения.

### Предметные модели

- `CaseModel`: GUID, досье, комментарии, даты и статус.
- `DossierModel`: персона UMMS, документы, адреса, дела, комментарии, статус, номер сценария и признаки отката.
- `FirstScenarioData`: даты выдачи/решения/заявления, регион, причина, тип адреса, страна, адресные/FIAS/домовые поля, сведения об аннулировании/выдаче и NewPdd.
- `AddressSearchModel`: тип адреса, населённый пункт, строение, актуальная дата, FIAS, страна и набор кодов/значений жилищных характеристик.
- `DocumentSearchModel`: тип критерия, орган, статус, период, выдавший орган, серия, причина и признаки поиска.

GUID в базовом классе — внутренний идентификатор модели; его нельзя считать FIAS ID или идентификатором UMMS без проверки присваиваний.

### UMMS SOAP

Описаны операции:

- `GetPersonAddresses`
- `GetPersonDocuments`
- `GetCountryDictionary`
- `GetDocumentDetail`
- `GetAddressDetail`
- `GetPersonCasesInfo`
- `IssueNewDocument`
- `RollbackIssueNewDocument`
- `SearchPersonFile`

Исторический proxy использует `Umms.UmmsNpImplService`. При переносе предлагается HttpClient + XmlSerializer с явным SOAP 1.1 envelope, асинхронными методами и CancellationToken. Необходимо сверить SOAPAction, namespace и wrapper с актуальным WSDL.

В XML-контрактах встречаются исторические имена/опечатки, например `SearchResposeType` и `previusDocumentStampInfo`. Их нельзя исправлять в wire-модели без подтверждения контракта.

### Адресный поиск

Историческая реализация обращается к Elasticsearch 1.2.1 по адресу localhost:9200 и индексу `i_address_object`. Отмечены формирование URL строковой конкатенацией, POST с пустым телом и разбор XML вместо ожидаемого JSON.

Для современной реализации нужны HttpClient, корректная сериализация JSON, кодирование параметров, таймауты, обработка статусов и проверка схемы ответа. Обновление Elasticsearch — отдельная миграция, не смешивать её с простым переносом на .NET 8.

### Обмен с мобильным модулем

TransferManager использует файлы `dat.umms`, `datMM.umms`, `datsynch.umms`, сериализацию XML и шифрование через StringCipher. В обмене встречаются `TransferModel` и `TransferDossierModel`.

Статусы досье, известные из перечисления:

1. Created
2. Exported to mobile
3. Synchronized
4. Error

Переходы статусов происходят в вызывающем коде, а не обязательно внутри TransferManager. Для восстановления жизненного цикла нужны все call sites.

### Печать и MRZ

PassportPaint содержит логику раскладки/печати и построения MRZ. Зафиксированы строки MRZ формата 2×44 символа и пользовательская транслитерация. Перед изменениями необходимо сверить алгоритм с применимой официальной спецификацией, проверить контрольные цифры, длины и даты.

## 3. Внешние зависимости и конфигурация

- UMMS SOAP endpoint (исторически встречался тестовый HTTP URL; не считать production).
- Elasticsearch/FIAS endpoint.
- SQLite-файлы.
- Съёмные носители.
- Принтер/USB-порт и драйвер печати.
- Tesseract OCR.
- Конфигурация URL сервисов и лимитов.

Секреты, реальные персональные данные и рабочие адреса сервисов не должны попадать в репозиторий. Для окружений использовать защищённую конфигурацию и шаблон `appsettings.example.json` без секретов.

## 4. Неустановленные факты

- Точная граница уже перенесённого кода на .NET 8.
- Актуальные production endpoints и WSDL UMMS.
- Текущая версия Elasticsearch и схема индекса.
- Полный контракт мобильного модуля и формат шифрования на обеих сторонах.
- Правила переходов статусов.
- Фактические точки сохранения/передачи NewPdd.
- Полный перечень UI-проектов, тестов и сборочных конфигураций.
