# Риски и технический долг

Оценки предварительные и основаны на фрагментах кода/описаниях, предоставленных для анализа. Перед исправлением требуется подтвердить актуальность проблемы в полном исходном коде.

| Приоритет | Область | Наблюдение | Риск / действие |
|---|---|---|---|
| Критический | Аутентификация | В LoginWindow встречается hardcoded `admin/admin`; `DialogResult` выставляется независимо от результата проверки | Возможен обход входа при проверке только DialogResult. Сначала исправить ветвление, затем внедрить реальный auth provider |
| Высокий | Криптография | StringCipher использует RijndaelManaged, статический salt и предсказуемую схему IV; нет аутентификации шифротекста | Не обеспечивает современную целостность/защиту от модификации. Нужен версионированный протокол, но только с согласованием мобильной стороны |
| Высокий | Файловый обмен | Нет явной версии формата, целостности, ограничений размера, атомарной записи и защиты от повторного импорта | Риск повреждения/подмены/повторной обработки файлов |

## Конкретные замечания

### LoginWindow

В одном из предоставленных фрагментов:

- `IsAuth` вычисляется сравнением с `admin/admin`;
- `e.Handled = true`;
- `DialogResult = true` устанавливается безусловно.

Проверяющий код, который смотрит только DialogResult, может считать неуспешный вход успешным. Минимальный локальный фикс — выставлять DialogResult=true только после успешной проверки; это не заменяет полноценную аутентификацию.

### StringCipher

Зафиксированы salt `tu89geji340t89u2`, RijndaelManaged, неявные параметры Rfc2898DeriveBytes и последовательное получение Key/IV. Decrypt выполняет один Read, что не гарантирует чтение всего потока. Изменение формата без проверки реализации мобильного приложения может сделать старые файлы нечитаемыми.

### TransferManager

Файлы `dat.umms`, `datMM.umms`, `datsynch.umms`; XML сериализация `TransferModel`/`TransferDossierModel`; шифрование через StringCipher. Проверки наличия файла отличаются между методами. Статусы обновляются в вызывающем коде — нужно исследовать все места вызова, чтобы восстановить state machine.

### SOAP

Нужно сохранить точные namespaces, wrapper elements и исторические имена элементов из WSDL. Нельзя исправлять опечатки в XML contract-моделях, если они являются частью фактического wire format.

## Не помещать в репозиторий

- реальные ФИО, паспортные данные, адреса, номера дел и досье;
- пароли, токены, private keys, production connection strings;
- реальные файлы обмена и необезличенные SOAP dumps;
- закрытые сертификаты и ключевой материал.
