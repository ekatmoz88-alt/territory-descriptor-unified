# План миграции АРМ «внешняя система» на .NET 8

## Цель

Перенести приложение с .NET Framework 4.5 на поддерживаемую современную платформу с сохранением бизнес-поведения и совместимости с external SOAP service и мобильным модулем.

## Этап 0. Инвентаризация и фиксация baseline

- Собрать все solution/project-файлы, ресурсы, конфиги и post-build scripts.
- Зафиксировать целевые платформы UI (WPF/WinForms) и разрядность.
- Составить список NuGet и native dependencies.
- Сохранить контрольные примеры входных/выходных SOAP XML и файлов обмена (без персональных данных).
- Зафиксировать текущие сценарии пользователя и результаты.

Критерий выхода: воспроизводимая сборка исходной версии и перечень зависимостей.

## Этап 1. Разделение слоёв

Рекомендуемая целевая структура:

- `external enterprise system.Domain` — модели и бизнес-правила;
- `external enterprise system.Application` — use cases, интерфейсы сервисов;
- `external enterprise system.Infrastructure` — SQLite, SOAP, Elasticsearch/external address directory, файловый обмен;
- `external enterprise system.Desktop` — WPF/WinForms UI;
- `external enterprise system.Tests` — unit/integration tests.

Не требуется одномоментно переписывать UI. Сначала вынести сетевые и файловые операции за интерфейсы.

## Этап 2. Перенос платформы

- Создать SDK-style проекты с `TargetFramework` `net8.0-windows` для Windows UI.
- Включить `UseWPF` и/или `UseWindowsForms` только для соответствующих проектов.
- Проверить COM, P/Invoke, драйверы печати, native OCR и архитектуру x86/x64.
- Удалить дублирующие AssemblyInfo-атрибуты при включении SDK-generated metadata.
- Переносить библиотеки по одной, фиксируя поведение тестами.

Важно: .NET 8 WPF/WinForms — Windows desktop stack. Если требуется запуск самого UI на Linux, это отдельное архитектурное решение, а не простая смена TargetFramework.

## Этап 3. external SOAP

- Получить актуальный WSDL и подтвердить production endpoint.
- Сохранить SOAP 1.1 и точные XML namespaces/wrapper elements.
- Реализовать HttpClient с IHttpClientFactory либо управляемым singleton lifetime.
- Добавить async API и CancellationToken.
- Настроить безопасный XML reader: DtdProcessing.Prohibit, XmlResolver = null.
- Проверять HTTP status до разбора ответа; ограничить размер ответа.
- Сверить SOAPAction и сериализацию всех девяти операций.
- Не логировать паспортные и иные персональные данные.

Критерий выхода: contract tests на обезличенных SOAP request/response fixtures.

## Этап 4. external address directory / Elasticsearch

- Зафиксировать версию сервера и mapping индекса.
- Сохранить совместимость с текущим индексом до отдельного решения об обновлении.
- Перейти на HttpClient и JSON DTO.
- Кодировать query parameters, задавать таймауты и обрабатывать HTTP ошибки.
- Добавить тесты на пустой ответ, частичный ответ, некорректный JSON и недоступность сервера.

## Этап 5. Файловый обмен и криптография

- Описать текущий бинарный/текстовый формат и сериализацию.
- Получить реализацию StringCipher мобильного модуля и тестовые векторы обеих сторон.
- Не менять salt/KDF/IV/шифр в существующем формате без согласованного протокола.
- Для нового формата определить version header, KDF, salt, nonce, authenticated encryption и проверку целостности.
- Реализовать чтение legacy + нового формата на переходный период.
- Добавить атомарную запись через временный файл, ограничения размера и защиту от повторного импорта.
- Проверять доступность носителя, свободное место и ошибки записи/извлечения.

Критерий выхода: двусторонние тесты совместимости с мобильным модулем.

## Этап 6. Безопасность и эксплуатация

- Удалить hardcoded credentials и тестовые значения.
- Исправить логику LoginWindow: успешный DialogResult только при успешной аутентификации; внедрить реальный auth provider.
- Перенести секреты из конфигов/кода в защищённое хранилище.
- Ввести структурированное логирование с исключениями, correlation ID и редактированием PII.
- Проверить права на файлы экспорта, временные файлы и съёмные носители.
- Провести threat modeling для локальных файлов, USB и SOAP.

## Этап 7. UI и тестирование

- Перевести долгие операции на async/await.
- Добавить отмену и индикацию прогресса.
- Защитить UI от некорректных индексов вкладок и null/неожиданных типов в converters.
- Проверить диспетчер исключений и логирование.
- Тестировать печать на поддерживаемом оборудовании.
- Добавить smoke tests на запуск, конфигурацию и основные пользовательские сценарии.

## Приоритеты

1. Аутентификация и секреты.
2. Контракт и совместимость файлового обмена.
3. SOAP/PII безопасность.
4. Сборка и разделение слоёв.
5. UI responsiveness.
6. Оптимизация и косметический рефакторинг.
