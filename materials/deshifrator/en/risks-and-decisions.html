Technical Risks & Engineering Decisions

Preliminary technical observations, risks, and potential engineering approaches.

Document status. This description is based on available project materials and selected code fragments. Unverified details and modernization proposals must not be interpreted as completed implementations.

Analysis status

The items below describe risk areas identified while reviewing selected code fragments and project descriptions. These are preliminary observations, not the findings of a full security audit. Each item must be verified against the complete, current source code before remediation.

Engineering decisions and trade-offs

SOAP compatibility

When modernizing the client, application domain models should be separated from XML wire models. This helps preserve the historical external-service contract even when its names or structure do not follow current conventions. Any change to the SOAP envelope, namespace, or SOAPAction must be checked against the WSDL and integration tests.

File-exchange compatibility

The mobile exchange format is a contract between two applications. Serialization and encryption changes should be released as a coordinated migration, with support for reading previous versions during the transition.

Separating migrations

Moving the application to a newer .NET version, upgrading Elasticsearch, and changing the file-exchange protocol should be planned as separate stages. This makes regressions easier to isolate and allows each change to be checked independently.

Configuration security

Service addresses, credentials, keys, and connection strings should not be hard-coded. Use environment variables or a secure secrets store; keep only templates with fictional values in the repository.

Information excluded from publication

  • real names, passport details, addresses, case numbers, or dossiers;
  • passwords, tokens, keys, salt/IV values, or certificates;
  • production connection strings and live service URLs;
  • real exchange files, non-anonymized SOAP responses, or document scans;
  • exports that could identify an individual or internal infrastructure.

Limitations

These observations are based on selected materials and require verification against the complete source code. Recommendations describe potential engineering improvements and do not imply that the changes have already been implemented.
