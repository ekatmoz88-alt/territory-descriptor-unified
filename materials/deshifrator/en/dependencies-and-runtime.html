Dependencies, Configuration & Runtime Boundaries

A review of the supplied archives and configuration files. This page describes the historical package contents; it is not a deployment guide.

Verification status. Installers and applications have not been executed. External service availability has not been tested. Configuration values are treated as package evidence, not as current production settings.

Application components

ComponentConfirmed evidenceInference boundary
Descriptor.exeWindows desktop application targeting .NET Framework 4.5; package includes WPF components, a TWAIN helper, Tesseract OCR and native x86/x64 libraries.Its application config does not establish a direct SOAP or Elasticsearch connection.
ModuleStationary.exeSeparate .NET Framework 4.5 WPF module with SQLite, dictionaries, a printing component and local FIAS configuration.A local database does not by itself prove synchronization with the mobile module.
ModuleMobile.exeSeparate .NET Framework 4.5 WPF module with SQLite, dictionaries, UMMS SOAP configuration and local FIAS configuration.A configured URL does not prove service availability or a successful integration.
Elasticsearch / FIASElasticsearch 1.2.1, Lucene 4.8.1, XML and river-csv plugins, and a pre-populated FIAS index directory.The index must not be replaced with an empty one or have lock files removed without investigation.

Configuration evidence

  • Descriptor.exe.config: targets .NET Framework 4.5; no confirmed SOAP connection string is present.
  • Descriptor_config.zip → Config.cfg: historical Windows paths for raster fonts, archive, database and Paint.NET.
  • ModuleStationary.exe.config: .NET Framework 4.5 and a local FIAS/Elasticsearch URL.
  • ModuleMobile.exe.config: .NET Framework 4.5, UMMS SOAP configuration and a local FIAS/Elasticsearch URL. Actual endpoint values are omitted from this public page.

Local SQLite databases

Mobile module: User, UserRole, UserAction.

Stationary module: Cases, Dossier, Person, Document, XML tables, user and audit tables.

This describes the supplied local database files. It does not establish the production database contents or a synchronization mechanism.

A Linux Elasticsearch launcher is included, but its configuration uses CMS garbage-collector options that are absent from modern Java releases. Compatibility with a modern Java runtime has not been established.

Analysis limitations

  • Installers and applications have not been executed.
  • External SOAP service availability has not been tested.
  • The pre-populated FIAS index must be preserved as a whole.
  • The ZIP warning for the empty Dics/ directory does not by itself prove executable-file corruption.
  • Any experimental execution requires an isolated environment and a copy of the original data.

Conclusion

The system should be documented as a set of separate Windows components with distinct local data and external dependencies. SOAP integration is evidenced by the mobile module configuration; FIAS/Elasticsearch is configured in both the mobile and stationary modules. OCR and scanning belong to the desktop application package.
